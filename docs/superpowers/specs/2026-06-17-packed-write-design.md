# Design: ZarrDaf + FilesDaf/ZipDaf packed/sharded WRITE

Date: 2026-06-17
Status: approved
Scope: dafr-native, branch `zarr-v3-packed-write` off `dev`
Reference: DataAxesFormats.jl `src/packed_format.jl` (+ `mmap_zip_stores.jl`,
`zarr_format.jl`); the existing dafr READ port `R/zarr_sharded.R` /
`R/files_packed.R` / `src/shard_codecs.cpp` / `src/crc32c.c`.

## 1. Problem & goal

dafr reads packed/sharded (`packed=true`) ZarrDaf and FilesDaf/ZipDaf stores
(`R/zarr_sharded.R`, `R/files_packed.R`) but writes only **flat** (uncompressed)
properties. The remaining-gap backlog (`dev/parity-audit-2026-06-11/REMAINING-GAP.md`,
"DEFERRED BACKENDS") lists **packed/sharded WRITE** as the open feature.

**Goal (maximal, chosen with maintainer):** write **full dual-format**
(`packed_format = "indexed+zipped"`) packed stores for **both** ZarrDaf and
FilesDaf/ZipDaf, defaulting to Julia's default codec
(`blosc_zstd_bitshuffle`), such that DataAxesFormats.jl reads what dafr writes
and vice-versa.

## 2. Decisions (resolved with maintainer)

| # | Decision | Choice |
|---|----------|--------|
| A | Parity target | **Full parity** - either language reads either store |
| B | Backends | **Both** ZarrDaf and FilesDaf (and ZipDaf where it shares the Files write path) |
| C | Codecs | **Match Julia default** (`blosc_zstd_bitshuffle`); also `blosc_lz4_bitshuffle`, `zstd`, `gzip` |
| D | ZIP framing | **Full dual-format everywhere** (incl. ZarrDaf's ZIP central directory + ZIP64 EOCD + `codec.json`) - byte-identical framing to Julia |
| E | API | `packed=` arg on constructors + R `options()` mirroring Julia's `DAF_PACKED_*` globals |
| F | Compressed-payload byte-equality | **Not promised** (see §8). Framing is byte-identical; payloads are functionally-equivalent |

### Non-goals
- Writing flat stores differently (the flat path is untouched; packed is opt-in).
- The `zstd_bitshuffle` / `gzip_shuffle` codecs (Julia marks these unsupported on
  the v3 sharded backend - skip).
- Bundling/vendoring a compression library (blosc/zstd stay `configure`-gated,
  identical to the read port).

## 3. Architecture

Mirror the read side: a storage-agnostic encoder core, consumed by thin
per-backend write integrations.

### New / extended units

- **`R/shard_encode.R`** (new) - the dual-format shard *encoder*, exact inverse of
  `R/zarr_sharded.R`. Pure R except compression calls. Public entry:
  `.shard_assemble(values, dtype, shape, inner_shape, codec, level)` -> one shard
  blob (`raw`). Pipeline:
  1. serialize element bytes (reuse `zarr_v3_encode_chunk` for fixed-width,
     `zarr_v3_encode_strings` for vlen-utf8);
  2. split into inner chunks in the grid's linear order (§6), fill-padding the
     partial last chunk to the full inner shape before compression;
  3. compress each chunk via `.shard_inner_compress()` (§4);
  4. build the start-located shard index (§5);
  5. wrap chunks in ZIP framing (`R/shard_zip.R`, §7);
  6. concatenate `[index][zip-framed chunks][central dir][EOCD region]`.
  Plus `.shard_should_pack(shape, elem_size, target_bytes)` and
  `.shard_inner_chunk_shape(shape, elem_size, target_bytes)` (§6).

- **`R/shard_zip.R`** (new) - ZIP dual-format framing only (largest, fiddliest
  unit; isolated for testing): local file headers, fixed-width-named central
  directory, ZIP64 EOCD region, per-codec ZIP method mapping, the gzip
  header-in-name special case, the `codec.json` STORED-sentinel entry.

- **`src/shard_codecs.cpp`** (extend) - encode mirrors of the decode wrappers:
  - `dafr_zstd_compress_cpp(raws src, int level)` -> raw zstd frame (`#ifdef HAVE_ZSTD`).
  - `dafr_blosc_compress_cpp(raws src, int level, std::string cname, int doshuffle, int typesize)`
    -> classic blosc1 chunk (`#ifdef HAVE_BLOSC`). Uses the blosc1 compress API
    with the compressor selected by name; bitshuffle via `doshuffle`.
  - Both `#else` branches `cpp11::stop()` with the same actionable
    "install c-blosc / libzstd and reinstall dafr" message as the read stubs.

- **`src/crc32.c` / `src/crc32.h`** (new) - standard **zlib CRC-32**
  (poly `0xEDB88320`, reflected), always compiled, table-based - a sibling of
  `src/crc32c.c`. The ZIP local/central headers carry zlib CRC-32 per chunk
  (distinct from the shard index's CRC-32**c**, which `crc32c.c` already
  provides). Hand-rolled to avoid a new system dependency. cpp11 wrapper
  `dafr_crc32_cpp(raws)`.

- **`R/cpp11.R` + `src/cpp11.cpp`** - regenerated by `cpp11::cpp_register()`.

### Write integration

- **ZarrDaf** (`R/zarr_format.R`, `R/zarr_v3.R`): `zarr_daf(..., packed = FALSE)`
  threads `internal$packed`. At each flat-write site, when packed and the
  component is over threshold, write the single outer-chunk shard blob
  (`zarr_v3_chunk_path(base, ndim)` = `c/0` / `c/0/0`) and emit a sharding-codec
  `zarr.json` via a new `zarr_v3_sharded_array_meta()`.
- **FilesDaf/ZipDaf** (`R/files_daf_write.R`, `R/files_io.R`):
  `files_daf(..., packed = FALSE)` threads `internal$packed`. When packed and over
  threshold, write `<name>.zip` (dense) / `<name>.<comp>.zip` (each sparse
  component) plus the packed descriptor JSON. ZipDaf reuses the Files shard bytes
  written into its store.

### Config (`R/` options resolver)

`.packed_opts()` reads, mirroring Julia's module globals:
- `dafr.packed_compression` (default `"blosc_zstd_bitshuffle"`)
- `dafr.packed_compression_level` (default `5`)
- `dafr.packed_target_chunk_kb` (default `8`)

Codec validation: requesting `zstd`/`blosc*` when the lib isn't built in
(`dafr_have_zstd_cpp()` / `dafr_have_blosc_cpp()` is FALSE) errors actionably at
write time. `gzip` is always available.

## 4. Codec support & the CRAN gate

| Codec | Encoder | ZIP method | Build dependency |
|---|---|---|---|
| `gzip` | base-R `memCompress(type="gzip")`; strip 10-byte header / 8-byte trailer to the raw DEFLATE payload | 8 (DEFLATE; gzip header relocated to name field, trailer as dead bytes) | none - **CRAN-clean** |
| `zstd` | `dafr_zstd_compress_cpp` | 93 (raw zstd frame) | `HAVE_ZSTD` |
| `blosc_zstd_bitshuffle` (**default**) | `dafr_blosc_compress_cpp(cname="zstd", doshuffle=BITSHUFFLE, typesize=elem_size, clevel)` | 0 (STORED) + `codec.json` | `HAVE_BLOSC` |
| `blosc_lz4_bitshuffle` | `dafr_blosc_compress_cpp(cname="lz4", ...)` | 0 (STORED) + `codec.json` | `HAVE_BLOSC` |

Packed write is **opt-in** (`packed=FALSE` default): the flat path and the
no-optional-lib CRAN build are untouched. `gzip` carries the CRAN test burden
(runs everywhere); `blosc`/`zstd` are exercised in the conda env where the libs
are present, exactly like the read tests.

## 5. Shard index (verified against the read port)

Start-located: `N` inner chunks -> `N*16` bytes of `(offset:u64 LE, nbytes:u64 LE)`
pairs, then a 4-byte **crc32c** (Castagnoli) over those `N*16` bytes. `N =
prod_d ceil(shape[d] / inner_shape[d])`. Empty/all-fill chunk sentinel =
`0xFFFFFFFFFFFFFFFF` for both fields. The first chunk's bytes begin immediately
after the index (the read port pins offset 89 for the 2-chunk score-vector
fixture: `2*16 + 4 = 36`-byte index, then the first ZIP local file header, then
the chunk). The encoder is the exact inverse of `.zarr_shard_index()`.

## 6. Threshold gating, inner chunk shape, grid order

**To pin against fixtures (Julia map, treat as needing verification):**
- **Threshold:** a component is sharded iff `shape[1] * effective_sizeof(eltype)
  >= DAF_PACKED_TARGET_CHUNK_KB * 1024` (8192 B default). `effective_sizeof` =
  `sizeof(eltype)` for fixed-width, `16` for strings. Applied **per first-dim**
  (so a wide matrix with short columns stays flat; each sparse component
  thresholds independently). Sub-threshold -> stay flat (the existing flat writer
  + reader already coexist with sharded components in one store).
- **Inner chunk shape:** `n_chunk_rows = min(target_bytes %/% sizeof(eltype),
  shape[1])`; vector -> `(n_chunk_rows)`, matrix -> `(n_chunk_rows, 1)`
  (column-slab chunks).
- **Grid linear order:** column-major (Fortran) over the inner-chunk grid -
  matches the read port (`R/files_packed.R` iterates col-chunks outer, row-chunks
  inner; `.shard_decode_matrix` in `R/zarr_sharded.R` documents the on-disk
  C-order-over-reversed-shape equivalence). The encoder must emit chunks in the
  exact order the decoder indexes them - pinned by round-tripping each fixture
  through the existing reader before trusting any abstract derivation.
- **On-disk shape:** ZarrDaf `zarr.json` stores the reversed `[ncols, nrows]`
  matrix shape (and reversed inner `chunk_shape`); the byte stream stays Julia
  column-major. FilesDaf descriptor `chunk_shape` is natural `[nrows, ncols]`.
  Both are already handled on read; the writer mirrors each.

## 7. ZIP dual-format framing (byte-identical target)

Layout: `[shard index]` then, per chunk in grid order, `[local file header][chunk
bytes]`; then (STORED codecs only) `[codec.json STORED entry]`; then `[central
directory]`; then the `[ZIP64 EOCD record][ZIP64 EOCD locator][legacy EOCD]`
region.

- **Per-codec method:** `zstd` -> 93 (entry data = raw zstd frame); `gzip` -> 8
  (entry data = raw DEFLATE payload; the 10-byte gzip header lives in the ZIP
  name field and the 8-byte gzip trailer follows as dead bytes, so a Zarr range
  from the name start spans a valid gzip stream); `blosc*`/other -> 0 STORED
  (entry data = codec output verbatim; a `codec.json` STORED entry after the last
  chunk records the inner pipeline for generic ZIP tools).
- **Fixed-width chunk names:** for STORED/zstd, `c/<i_N>/.../<i_1>` with each
  dimension zero-padded to `ndigits(chunks_per_dim - 1)`, reversed (C-order);
  fixed length per archive so central-directory entries are O(1)-addressable. For
  DEFLATE/gzip the 10-byte name field is the repurposed gzip header (chunk index
  base64-encoded in 3 bytes).
- **ZIP64:** local headers and central-directory entries use ZIP64 extra fields
  (sizes/offsets as `0xFFFF...` sentinels in the base record, real values in the
  extra); the trailing region is ZIP64 EOCD record (56 B) + locator (20 B) +
  legacy EOCD (22 B) = 98 B.
- All exact byte offsets/constants are pinned against Julia fixtures + validated
  by an independent ZIP reader (`unzip -l` / `zip::zip_list`) in tests, not
  trusted from the format map alone.

## 8. The parity caveat (explicit)

**Framing is byte-identical** to Julia (shard index, ZIP local/central headers,
fixed-width names, ZIP64 EOCD, `codec.json`). The **compressed chunk payloads are
NOT guaranteed byte-identical** - blosc/zstd/zlib output can differ across library
versions even at the same level/params. The verified parity guarantees are:

1. dafr writes -> dafr reads back identical values (in-process round-trip).
2. dafr writes -> DataAxesFormats.jl reads back identical values (the interop goal).
3. Byte-identical *framing* vs committed Julia fixtures.

Payload byte-equality is best-effort / observed-in-env, asserted only where it
holds, never relied upon for correctness.

## 9. ZarrDaf sharded `zarr.json` (write)

`zarr_v3_sharded_array_meta()` emits an `array` node whose outer `chunk_grid`
chunk_shape equals the full (reversed-for-matrix) `shape` (one outer chunk), and
whose single codec is `sharding_indexed` with configuration: inner `chunk_shape`,
inner `codecs` (`bytes` + the compressor), `index_codecs` (`bytes` + `crc32c`),
`index_location: "start"`; plus the `daf_packed_format: "indexed+zipped"`
attribute. The exact inner-codec JSON block (e.g. blosc `cname`/`clevel`/
`shuffle`/`typesize`) is pinned to what Julia writes and what dafr's own reader
parses - verified by fixture diff, since the read path keys only off the
compressor name.

## 10. FilesDaf/ZipDaf packed descriptor (write)

Each packed dense property / sparse component descriptor JSON gains:
`packed_format: "indexed+zipped"`, `chunk_shape` (natural `[nrows, ncols]` /
`[n]`), `compression` (the codec symbol), `compression_level`, `index_location:
"start"`. File naming: `<name>.zip` (dense) and `<name>.<comp>.zip` (sparse
`colptr`/`rowval`/`nzind`/`nzval`). nzval omitted for all-true Bool, as today.

## 11. Verification plan (fixture-driven)

- **Unit:** `test-shard-encode.R` (index bytes, chunk split + fill-pad, each codec
  round-trips through the existing `.zarr_inner_decode`); `test-shard-zip.R` (the
  blob is a legal ZIP per `zip::zip_list`/`unzip`, names/methods/EOCD correct);
  crc32 (zlib) canonical check value (`"123456789"` -> `0xCBF43926`).
- **ZarrDaf:** `test-zarr-packed-write.R` - `packed=TRUE` write of dense vector,
  dense matrix, sparse matrix, strings, mixed flat+packed store; read back via the
  existing reader; assert values + that the existing read fixtures and the
  freshly-written stores agree.
- **FilesDaf:** `test-files-packed-write.R` - same matrix of cases for `.zip`
  shards + packed descriptors.
- **Interop:** `test-zarr-packed-write-interop.R` / `test-files-packed-write-interop.R`
  - DataAxesFormats.jl opens a dafr-written packed store and round-trips values
  (skip when the Julia env / optional lib is absent), mirroring the read port's
  live interop test.
- **Framing byte-diff:** where a Julia fixture and a dafr write encode the same
  logical data with the same codec, diff the framing regions (index, headers,
  central dir, EOCD) for equality; assert value round-trip (not payload bytes) for
  the compressed regions.
- **CRAN no-lib:** a build with empty `configure` substitutions - flat tests pass,
  `gzip` packed write/read round-trips, `blosc`/`zstd` packed write errors
  actionably and those tests skip.

## 12. Phasing (-> writing-plans)

1. C encoders (`dafr_zstd_compress_cpp`, `dafr_blosc_compress_cpp`) + `src/crc32.c`
   zlib CRC-32 + cpp11 regen + unit tests (crc32, decompress(compress(x)) == x).
2. `R/shard_encode.R` core: serialize -> chunk -> compress (`gzip` first,
   dependency-free) -> index -> **Zarr-index-only** blob; verify through the
   existing `.shard_decode_*` reader (no ZIP yet).
3. `R/shard_zip.R`: full dual-format framing; validate as a legal ZIP and that the
   read port still parses the indexed blob.
4. ZarrDaf write integration: `packed=` arg, `.packed_opts()`, threshold gating,
   `zarr_v3_sharded_array_meta()`, round-trip + interop tests.
5. FilesDaf/ZipDaf write integration: `packed=` arg, packed descriptors, `.zip`
   shard files, round-trip + interop tests.
6. Codec-absent errors, docs (constructor `packed=`/options, NEWS, DESCRIPTION
   `SystemRequirements`), full suite + CRAN no-lib check; flip the
   REMAINING-GAP.md "packed/sharded WRITE" deferred bullet.

Each phase is independently testable; phase 2's `gzip` path is CRAN-clean; the
optional-lib capability lands in phases 1/4/5 behind the existing `configure` gate.

## 13. Risks

- **Grid order / per-chunk scatter inverse** - mitigated by round-tripping every
  fixture through the existing reader before trusting the encoder.
- **ZIP64 / fixed-width-name / gzip-name-trick byte exactness** - mitigated by
  independent ZIP-reader validation + Julia fixture framing diff.
- **blosc1 encode params (cname/clevel/bitshuffle/typesize)** matching what the
  reader's `blosc_decompress` expects - mitigated by C-level
  `decompress(compress(x)) == x` unit tests and the interop round-trip.
- **Format-map drift** - the Julia format details in §6/§7/§9 came from an
  automated source read; all load-bearing constants are pinned against real
  fixtures + the actual `packed_format.jl` during implementation, not trusted
  verbatim.
