# Julia ↔ R test-leaf coverage audit (2026-05-19)

Comparison of `~/src/DataAxesFormats.jl/test/*.jl` (the Julia test
corpus dafr ports from) against `tests/testthat/test-*.R`. Extraction
method: every `nested_test("…")` leaf path on the Julia side, every
`test_that("…")` block on the R side. Per-file Julia leaves are then
fuzzy-matched against R test_that names in the corresponding R files;
low-score leaves are spot-checked against the full R suite by keyword.

Source of truth:

| Side  | Files | Leaves / blocks | Assertions          |
|-------|-------|-----------------|---------------------|
| Julia |  21   | 1010 leaves     | 2075 `@test*` calls |
| R     | 205   | 2642 test_that  | 4733 `expect_*`     |

R has ~2.6× more `test_that` blocks than Julia has nested_test
leaves, so on aggregate the suite is well-covered. The audit is
about specific topics where R doesn't cover what Julia does.

## Real gaps (R should add tests)

### G1. `zarr_convert.jl > zarr_to_files > errors` (5 leaves)

Julia tests every error path for `zarr_to_files`:

- `bad_source_name`
- `http_source`
- `missing_source`
- `zip_source`
- `not_a_daf_zarr`
- `destination_exists`

R has the symmetric `files_to_zarr` error tests but not the
`zarr_to_files` direction. Effort: half a day - mirror each
existing `test_that("files_to_zarr errors when ...")` block.

### G2. `data.jl > zarr > non_canonical/*` (8 leaves)

Julia exercises read-back of Zarr arrays written with non-default
chunk / compression layouts:

- `chunked_dense_vector`, `compressed_dense_vector`,
  `chunked_compressed_dense_vector`, `chunked_string_vector`
- `chunked_dense_matrix`, `compressed_dense_matrix`
- `compressed_sparse_vector`, `compressed_sparse_matrix`

dafr's `R/zarr_v2.R` reads `chunks` and `compressor` from `.zarray`
(see `zarr_v2_decode_chunk`), so it *should* handle these - but
nothing in `test-zarr-*.R` writes a fixture with non-default chunks
or `blosc` / `zlib` compressors. Effort: half a day.

### G3. `data.jl > zarr > http > {open, invalid_mode, not_a_daf, named}` (4 leaves)

Read-only HTTP-backed ZarrDaf. R has
`test-http-store.R::zarr_daf rejects writable HTTP modes` and
`test-http-live.R` but not the specific Julia-parity error paths.
Effort: 2 hours.

### G4. `data.jl > zarr > zip > {overwrite_scalar, single, empty_crc, multi}` (4 leaves)

Zip-backed zarr operations. R has mmap-zip-store tests and
zarr-zip-roundtrip, but the specific paths Julia exercises at the
daf API level on a `.daf.zarr.zip` store aren't enumerated.
Effort: 2 hours.

### G5. `mmap_zip_stores.jl > truncate_discards_existing_archive` (1 leaf)

Truncate semantics on an existing archive. Not in any
`test-mmap-zip-store-*.R`. Effort: 30 minutes.

### G6. `mmap_zip_stores.jl > append_past_max_file_size_errors` (1 leaf)

Rejection when appending past the platform's max-file-size threshold.
Not in R. Effort: 30 minutes (may need to skip on platforms without
the resource limit available).

### G7. `data.jl > set_matrix! > named > {!rows, !columns} > name` (2 leaves)

`set_matrix` with a named matrix whose dimnames don't match the
axis entries - error path. Not enumerated in R. Effort: 15 minutes.

### G8. `copies.jl > matrix > sparse > {superset, disjoint} > {rows, columns} > empty > {!zero, zero, nothing, value}` (12 leaves)

R's `test-copies-matrix.R` covers `copy_matrix: sparse source +
source-is-subset + empty=0 stays sparse` and a few neighbouring
cases. Julia walks the full grid of (sparse) × (axis relation:
superset / disjoint) × (dimension: rows / columns) × (empty mode:
literal value / sentinel zero / nothing / non-zero). The 12 unmatched
leaves cluster around `sparse × (superset|disjoint) × empty result`
- corner cases where source and destination axes don't overlap.
Effort: 1 day (large surface, but each test is short).

### G9. `cache_groups.jl > h5df > {reads_cache_as_mapped, empty_fills_cache_as_mapped}` (2 leaves)

`H5dfFormat` cache-group classification. dafr supports `.h5df` via
`R/open_daf.R` and `R/anndata_format.R`, but `test-cache-group.R`
only exercises `MemoryDaf` and `FilesDaf` - no h5ad reads-cache-
as-mapped test. Effort: 2 hours.

## Documented divergences (no port intended)

### D1. `read_only.jl` (54 leaves, 310 @test calls)

Tests Julia AbstractArray wrappers: `SparseArrays.ReadOnly`,
`NamedArrays.NamedArray`, `permute_dims`, `transpose`, `adjoint`,
`is_read_only_array`. R has no analogue for any of these as
first-class types. `test-read-only-jl-parity.R` carries a single
`skip("R divergence CR_ARRAY: ...")` documenting the decision.
The dafr-level read-only API (the `read_only(daf)` wrapper, a
different concept) is covered in `test-read-only-daf.R`, chains,
and views.

### D2. `keys.jl` (4 leaves)

Tests `pairs_as_dict` - converts Julia pairs/named-tuples/`Dict`s
to a canonical `Dict`. R has native named lists; no helper is
needed and no port is required.

## Methodological caveats

1. **Fuzzy file-name + token-overlap mapping.** I matched Julia leaf
   paths to R test_that names by token-overlap. Low scores can be
   false negatives when R uses different vocabulary (e.g. "decompresses
   method-8 (deflate) entries" vs `reopen_read_only_foreign_deflate_archive`).
   Spot-check by keyword across the FULL R suite confirmed the gaps
   above are real (no R test mentions the topic).

2. **`@test` count vs `expect_*` count is unreliable.** R uses
   one-expect-per-`test_that` more often than Julia uses one-`@test`-
   per-`nested_test` leaf, so headline ratios are noisy. Per-leaf
   matching is the right granularity.

3. **`data.jl` is split across 23 R files.** I pooled their
   `test_that` names; coverage of the broad data.jl surface (writes,
   reads, axes, matrices, dataframes, zarr, mmap, http) is good in
   aggregate, but specific zarr/http/non-canonical paths drop out.

## Recommendation

Land the small gaps first (G3-G7, ~half a day), then decide on G1
(zarr_to_files errors, half day) and G2 (zarr non-canonical, half
day). G8 (copies sparse-axis grid) is the largest single chunk - a
day on its own. G9 is a quick add.

Total estimated effort to close the gaps: **2-3 person-days**.
None of the gaps surface known correctness bugs in dafr; they are
testing-coverage gaps where a Julia-side scenario isn't exercised
on the R side.
