## Prioritised follow-ups

### P0 (decision) - `dafrjulia` deprecation
The renamed wrapper is **broken against DAF 0.3.0**: its tests hit
`MethodError`s on `filled_empty_sparse_vector!/matrix!` (signature changed in
0.3.0); macOS R-CMD-check red since ~2026-05-01 (ubuntu passes only because it
caches an older DAF). Native `dafr` now covers the 0.3.0 formats. **Decide:**
archive/deprecate the wrapper with a README pointer to `dafr` (recommended -
don't maintain two R packages), OR port its tests/calls to the 0.3.0 API. Until
decided, `tanaylab/dafrjulia` CI stays red.

### P1 - dense parallel compute kernels (perf, the rest of old Item 4)
Dense matrix `>| Sum` (~2.3x) and `% Abs`/`Round`/`Clamp`/`Convert` (~3.7x) are
single-threaded R vs parallel Julia. The `% Log` per-call-overhead lever is
already taken. Add OpenMP dense reduction + eltwise kernels (template:
`src/kernel_log_dense.cpp` + the `.apply_eltwise` fast-path in
`R/query_eval.R`). Separately, the cold `get_matrix` residual is the axis-name
vlen-utf8 decode (~70ms for 4000+2500 entries, cached after first touch) -
a decode-caching follow-up, not the chunk read. Benchmark via
`benchmarks/efficiency-gaps.{R,jl}` (see `efficiency-gaps-results.md`).

### P1 - feature-blocked parity gaps (the skip-ID backlog)
Each is a real feature, tracked by skipped `*-jl-parity.R` tests + divergence
notes in `dev/`. Pick from:
- **Builder API (C3)**: `empty_dense_vector!/empty_sparse_vector!` +
  matrix variants. Unblocks several cache-group / chain / builder tests at once.
- **Concat**: M1 merge wildcards (`ALL_VECTORS`/`ALL_MATRICES => MERGE_*`),
  M5 `memory_daf` sparseVector support -> unblocks M2 sparse-preserving
  `MERGE_COLLECT_AXIS`, M4 `prefixed=` override semantics.
- **Views**: V7 reject a vector-query bound to a scalar; V1-V6 + view matrix
  relayout tracking.
- **Reorder**: R5 multi-writer atomic reorder; R6 `memory_daf` reorder
  crash-recovery atomicity.
- **Chains**: C1 singleton-chain identity optimization.
- **Queries**: E3-E11 deferred parser/evaluator divergences (matrix-slice
  masks, top-level comparators, count ops, auto-relayout). Start from
  `2026-05-03-queries-jl-parity-divergences.md`.

on a minimal box.

## Accepted divergences (do NOT chase without a kernel rewrite)
- **E1** `>> Median([.. NaN .. +-Inf ..])` = `NaN` (R) vs `-Inf` (DAF.jl). Every
  other reduction on such input is NaN in both. R's NaN is arguably more
  correct. Pinned by `test-reductions-special-values.R`; `FINDINGS.md` E1.
- **E11** `as_axis` `InexactError` on integer-typed reductions - R kernels
  promote int->double, losing the signal. `queries-jl-parity-divergences.md`.
