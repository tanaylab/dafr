## Remaining work (prioritized)

### 1. Zarr v2 → v3 port (large; the real "re-fix zarr for 0.3.0")
DAF 0.3.0 moved ZarrDaf to the **Zarr v3** on-disk format and *rejects v2
stores*; dafr's ZarrDaf (`R/zarr_v2.R`, `R/zarr_format.R`, `R/zarr_store.R`)
is entirely Zarr v2. R↔Julia zarr interop currently holds only vs DAF ≤ 0.2.x
(the 3 round-trip tests skip when env DAF ≥ 0.3.0 via
`.daf_jl_uses_zarr_v3`). A v3 port means, against `DataAxesFormats.jl`
`src/zarr_format.jl` @ 0.3.0:
- group/array metadata in `zarr.json` (not `.zarray`/`.zgroup`/`.zattrs`);
- daf marker as a root-group **attribute** `{"daf":[major,minor]}` (not an
  array);
- v3 chunk keys (`c/0/0`) and the v3 codec pipeline / sharded arrays;
- the "packed" dual ZIP+Zarr-v3-shard payloads (the directory-as-Zarr view).
Decision needed: support v3 read-only first, or read+write; keep v2 read for
back-compat with old dafr stores?

### 2. Phase-2 dense compute kernels (medium)
Dense matrix reductions (Sum/Mean/Max/Min/Var/Std/Median) and the
`% Abs`/`% Round`/`% Clamp`/`% Convert` eltwise ops are single-threaded
(`R/query_eval.R::.apply_reduction_fast`, `R/operations.R`); Julia
parallelizes them. Benchmarked gap 2-6×.
**Important finding:** the `% Log` 6.4× gap is *mostly query-path overhead*,
not the kernel - base-R `log2(M+1)` is 154 ms, Julia 61 ms, but `get_query`
is 395 ms (≈240 ms of alloc/cache/dispatch on a warm matrix). So adding
kernels closes the raw-compute gap but the bigger lever for query latency may
be reducing per-call result-allocation / cache-store overhead. Profile the
`get_query` path before sinking effort into more kernels.

### 3. FilesFormat 1.1 + 0.3.0 "packed" properties (medium)
- dafr currently *reads* 1.1 and *writes* 1.0 (1.0 is readable by 0.3.0).
  Decide whether to write 1.1 too.
- Packed (`.zip`, chunked+compressed, `packed_format` key) sparse/dense
  components are currently *rejected*. Reading them (the
  "directory-as-Zarr-with-hardlinks" payloads) is the 0.3.0 "bells and
  whistles" the author said to skip - revisit only if real repos use them.
